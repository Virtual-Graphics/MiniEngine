在 [a005](./a005_集成imgui.md) 中我们指出编辑器应该需要一个功能：将渲染结果保存在 RenderTarget 上，ImGUI 纹理直接采样 RenderTarget 中的 Color Attachment 进行呈现以实现 Viewport Panel，所以 Viewport Panel 是我们不可或缺的一个 Panel。除此之外我们还在 [a005](./a005_集成imgui.md) 中提到在 Editor 中我们需要启用 ImGUI 的 docking 功能，目前我们不打算实现 Multi Window 因为在遥远的未来（也许 3-4 个月后）我们的确考虑加入 Vulkan ，而在 Vulkan 中支持 Multi Window 并不是一件特别简单的事。

除了上面提到的 Viewport Panel 我们至少还需要 Inspector Panel、Hierarchy Panel（我们现在的 Scene Graph 还不支持 Hierarchy，实现扁平结构就行）。

具体的我们应该实现一个 Editor Context 这里 EditorContext 管理跨面板共享的编辑状态，所有的 Panel 都可以从中获取想要的 Scene 信息，这样可以解耦各个 Panel。需要注意的是目前我们的 Entity 内部保存了 Scene* ，在切换 Scene 时我们需要先清空选中的 Entity ，再切换 Scene，否则可能保留指向旧 Scene 的 Entity。

我们还需要实现独立的 Editor Camera，我们在 [a004](./a004_基本的ECS架构.md) 中已经在设计 Scene Extractor 时预留了相机覆盖接口。Editor Camera 应该实现第一人称相机控制，长按鼠标右键时进入 Editor Camera 控制状态，WASD 进行前后左右移动，QE 进行上下移动，鼠标滚轮控制编辑器相机的移动速度。

Viewport Panel 应该在鼠标左键或右键点击图像区域时都能进入焦点状态。

Hierarchy Panel UI 上目前只需要扁平节点树，操作上支持右键空白区域创建 Entity，左键选中 Entity 同步信息到 EditorContext，右键 Entity 删除 Entity



目前我们还没有 Project System ，Scene 也不能序列/反序列化，所以先创建一个默认的场景用于展示，未来我们会将这个默认的场景去掉改为加载真实的 MiniEngine Project。

## 第一版实现

编辑器作为 `apps/editor` 下的独立应用，复用 `mini_app_imgui`。`mini_editor` 是应用侧静态库，供编辑器可执行文件和面板交互测试共用；引擎内核没有增加 ImGui 依赖。

- `EditorLayer` 组织帧流程、默认布局、相机输入和渲染提交。
- `EditorContext` 持有当前 Scene 和选中实体句柄；替换 Scene 时先清空选择。每次读取选择都会检查句柄有效性，删除后即使 EnTT 回收了实体索引，也不会误选新实体。
- `EditorCamera` 只处理相机位置、朝向和速度，不修改 Scene 中的 CameraComponent。
- `ViewportPanel` 持有 RenderTarget，测量可用图像区域并反馈焦点和相机控制请求。
- `HierarchyPanel` 和 `InspectorPanel` 通过 EditorContext 共享选择，不相互持有引用。
- `create_default_scene()` 创建静止的 Bunny、地面、方向光、环境和场景相机，使用 Renderer 创建网格、材质资源。

默认布局是左侧 Hierarchy、中央 Viewport、右侧 Inspector。仅在没有已保存布局或选择 `View > Reset Layout` 时建立默认布局。用户调整后的 Docking 布局保存到工作目录中的 `mini_editor.ini`，这个文件不进入版本控制。关闭的 Panel 可以从 View 菜单重新打开。

### 视口与帧时序

`on_update()` 中调用 `begin_frame()`，构建 DockSpace 和各个 Panel，更新编辑器相机，再调用 `end_frame()` 完成 UI 绘制数据。

Viewport 根据内容区域大小和 framebuffer scale 确定实际渲染尺寸。尺寸变化时，先调整 RenderTarget，再获取新的 Color Attachment 纹理 ID 并记录 `ImGui::Image()`；OpenGL 图像使用上下翻转的 UV。折叠、被其他停靠标签遮住或内容尺寸不足一个逻辑像素时，跳过视口场景渲染。

`on_render()` 使用 `SceneExtractor::Options::camera_override_` 提供编辑器相机，将 Scene 渲染到视口 RenderTarget，然后恢复并清空窗口默认帧缓冲，最后调用 `ImGuiIntegration::render()` 提交 UI。UI 提交时采样的是本帧已经渲染好的颜色纹理。

### 相机交互

- 在 Viewport 图像区域按下右键时聚焦视口，并进入相机控制；仅获得焦点不会启动相机。
- 控制期间隐藏光标、启用 SDL 相对鼠标模式，鼠标位移控制朝向，俯仰角限制为 ±89°。
- W/S 沿观察方向前后移动，A/D 沿相机横向移动，Q/E 沿世界 Y 轴向下/向上移动。
- 键盘移动使用帧时间，组合方向归一化；鼠标旋转按相对位移计算。
- 控制期间滚轮按倍率调整速度，范围为 0.05～1000 单位/秒，初始为 5 单位/秒。
- 松开右键、按下 Escape、窗口失焦、视口失焦或隐藏时退出控制。窗口仍有输入焦点时恢复光标原位置；失焦时不移动系统光标。
- 在其他区域按下右键后移入 Viewport，不会启动相机控制。

### 实体与属性操作

Hierarchy 左键选择实体，点击空白取消选择；右键空白菜单创建并选中新 Entity，右键实体菜单删除对应 Entity。创建、删除放在实体列表遍历之后执行；删除当前选择时同时清空 Inspector。

Inspector 支持名称编辑、只读 UUID、Transform、MeshRenderer 可见性及只读资源句柄、Camera、Light 和阴影、Environment。旋转角在 UI 中显示为度数，组件内部保持弧度；限制零缩放、零光方向和退化的投影范围。当前不包含组件增删、材质编辑、视口拾取、父子层级、撤销重做和运行模式。

### 构建与验证

```powershell
cmake --preset clang-debug
cmake --build --preset clang-debug --parallel 8
ctest --test-dir build --output-on-failure
& .\build\bin\editor.exe
```

编辑状态和相机测试可在关闭 BUILD_APPS 时运行；无窗口的 ImGui 面板交互测试随 BUILD_APPS 开启，覆盖选择、同名实体、创建/删除菜单、文本编辑和零缩放保护。

本次使用 Windows、clang-cl Debug 和 Radeon RX 580 的 OpenGL 4.6 环境验证。真实 OpenGL 冒烟验证覆盖离屏纹理、场景与 UI 绘制、窗口缩放、右键捕获与释放、Escape、窗口失焦、布局恢复和销毁清理；另验证 BUILD_APPS=OFF 的内核构建不包含 ImGui。
