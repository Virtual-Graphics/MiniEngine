# 构建基本的渲染器架构

这个项目一开始写的时候，我打算是写一个紧凑性的模块间互相耦合的引擎，但是在封装 OpenGL 时或一些其他时间，我也一直在想这个引擎的架构，我对耦合的渲染模块还是不是很喜欢，所以我打算把渲染器打造成能独立工作的模块，对此我们需要定义好渲染器的接口供其他模块 / 开发者使用。除此之外我们应该定义好现阶段渲染器应该提供的功能，不能在目前阶段把所有高端的渲染效果全部加进去（否则我们就是在开发渲染器，而不是游戏引擎了），也就是我们需要约束现有阶段渲染器的功能边界。

我们先考虑以什么形式将 Scene 中的需要渲染的数据传递给渲染器，因为我们的渲染器是独立的和运行的模块，所以我们不能依赖于任何具体的数据结构，所以我们应该定义一种数据 schema，其他模块按规范填充这个数据，调用并传递数据给渲染器然后渲染器输出结果。除此之外有时候我们还希望调用渲染器的一些底层接口类似于 Gododt 的 RenderingDevice（RHI），以及修改渲染器的一些中间层如修改渲染管线等等。我们的渲染器应该直接搭建在类似 Goodt RenderingDevice 的功能基础上。

## 第一版本渲染器应该支持哪些功能
定义第一版数据契约 （Schema） / 数据接口（但是不应该有版本号这种参数，因为我们将长期处于内部开发阶段，不会真正的投入使用（也许 3-4 年后吧））  
外部能填充这个数据接口并传递给 Renderer::render(RenderData data) 接口进行渲染。  
向外暴露 RHI （目前是 gfx ）这需要外部用户自行维护一套渲染管线，先保留。  
支持 Forword Rendering Pipeline (后期改为 Deferred Rendering Pipeline)。  
Blinn-Phong Rendering （后期改为 PBR）    
固定 Linear Pipeline（shadow pass -> base pass）（后期改为 Frame Graph ，并实现可编程渲染管线）  
固定 Material （blinn phong ）参数 （后期实现 Material System）  
固定 Shader （后期实现 Shader System）   
可以先做 Frustum Culling   
不久的未来我们还希望将渲染器的结果呈现在 ImGui 的纹理上，并且我们的渲染器不应该直接耦合 ImGui ，所以我们需要提供一种渲染到纹理的接口，ImGui 编辑器使用这个接口获得数据后进行桥接。（也许我们可以都统一为渲染到 RenderTarget ，由引擎内部将 RenderTarget 呈现到 Swapchain 这样接口能统一）引擎内部自己使用渲染器暴露的 RHI 渲染 ImGui ，或者使用引擎自带的 RHI。    

具体的，我们需要定义以下结构 / 接口  
- 抽象 Camera 并实现抽象 Perspective Camera & Orthogonal Camera 。  
- RenderData 应该包含一帧画面中需要渲染的所有数据，包括相机参数，环境参数，灯光参数，几何参数等等。  
- 渲染器应该提供类似 Renderer::render(RenderData) 的接口。  
- GPU resrouce 如 渲染器内部的 Mesh Light Enviroment Material 等等

此外，外部应该实现一个 extractor 输入一个 scene 输出一个 RenderData (需要等待 scene 模块第一个版本完成)  

- Renderer 不 include Engine 的任何头文件  
- Engine 不 include Renderer 内部的实现细节，除了 RenderData / RHI 头。 
- Extractor 是 Engine 侧的适配层，把 Scene 翻译成 RenderData。
